You are a senior full-stack engineer and product designer. Build an MVP called “Hoster” — a B2C, mobile-first web app (PWA) for solo short-term rental hosts (1–10 listings). The goal is calm, fast daily control over bookings, availability, and guest messages. The app must SUPPORT a multi-channel journey from day one (Airbnb, Booking.com, Expedia, TripAdvisor), but for MVP we will implement them as MOCK providers with a clean adapter interface so we can later swap to real APIs/aggregators.

IMPORTANT
- B2C: single-user accounts (no teams).
- Mobile-first UI only (phone layout). Bottom tab bar.
- Keep it shippable: implement a working multi-channel experience using MOCK providers.
- Do NOT scrape any websites. No unofficial automation. Only design with provider adapters + placeholder connectors.
- Structure the code so adding real providers later is a drop-in change.

TECH STACK
- Frontend: Next.js (App Router) + TypeScript + Tailwind (mobile-first)
- Backend: Next.js Route Handlers (API routes) + Server Actions
- Database: PostgreSQL with Prisma ORM
- Auth: NextAuth (Credentials provider)
- Background jobs: simple cron endpoints + DB cursor polling (no external queue for MVP)
- Notifications: in-app notifications (push optional placeholder)

CORE USER JOURNEY (ONBOARDING MUST SHOW MULTI-CHANNEL)
1) Sign up / Login
2) Connect Channels screen shows 4 options with logos:
   - Airbnb
   - Booking.com
   - Expedia
   - TripAdvisor
3) User can connect 1–4 channels (MOCK connect)
4) Import listings from connected channels
5) Map each external listing -> internal Listing (auto-map if names match; otherwise user selects)
6) First sync completes and Home shows “All channels synced ✅” or warnings per channel

KEY IDEA
- Internally, Hoster uses one unified model:
  - Listings, Reservations, Conversations, Messages, CalendarDays
- Each channel has a Provider Adapter that can:
  - listListings()
  - listReservations(sinceCursor)
  - listMessages(sinceCursor)
  - pushCalendarBlock(listingExternalId, dateRange)
  - sendMessage(conversationExternalId/reservationExternalId, body)
- The UI and internal services never depend on channel-specific fields.

DOUBLE BOOKING PREVENTION (MVP LOGIC)
- A listing can be connected to multiple channels.
- Before inserting/updating any CONFIRMED reservation:
  - Check for overlaps on the same internal listing across ALL channels.
- If conflict:
  - Do not overwrite existing confirmed reservation.
  - Create Notification type=DOUBLE_BOOKING_RISK
  - Mark the channel connection status=ERROR with lastError describing conflict.

CALENDAR SOURCE OF TRUTH (MVP)
- RESERVED days are derived from CONFIRMED reservations across channels.
- BLOCKED days are stored as CalendarDay with source=MANUAL.
- Rendering priority:
  1) RESERVED (if any reservation covers date)
  2) BLOCKED
  3) AVAILABLE

MOCK PROVIDERS (MUST FEEL REAL)
Implement 4 mock providers:
- MockAirbnbProvider
- MockBookingProvider
- MockExpediaProvider
- MockTripadvisorProvider

Each provider should:
- Seed 1–3 external listings with distinct IDs
- Seed 5–15 reservations across next 60 days
- Seed message threads per reservation
- On each sync, randomly generate:
  - new inbound message
  - reservation created
  - reservation canceled
  - reservation updated (date change)
- Provide stable deterministic behavior per user (e.g., seeded random by userId) to avoid chaos

SYNC ENGINE (SERVER-SIDE)
Implement endpoints:
- POST /api/providers/connect (channelKey) -> marks ChannelConnection CONNECTED and seeds provider state
- POST /api/providers/disconnect (channelKey)
- POST /api/sync/run -> runs sync for all CONNECTED channels:
  - fetch listings/reservations/messages since cursor
  - upsert into DB
  - update cursors + lastSyncAt
  - create notifications for new booking/message
- GET /api/sync/status -> per-channel status for UI

CRON REMINDERS (SERVER-SIDE)
- POST /api/cron/daily (protected by CRON_SECRET)
Runs once per day:
- If autoCheckinMessage enabled: for reservations with checkIn = tomorrow, send “Check-in instructions” via providerAdapter.sendMessage (MOCK) and log as OUTBOUND message
- If cleaningReminder enabled: for reservations with checkOut = today, create Notification “Cleaning reminder”
