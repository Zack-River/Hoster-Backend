----------------------------------------

- Open a bottom sheet/modal showing:
  - Guest avatar (placeholder if none)
  - Guest name
  - Reservation dates
  - Property name
  - Channel badge
  - Optional contact fields if available

----------------------------------------
C) DATA / LOGIC
----------------------------------------
Assume reservations have statuses.
Add/confirm these statuses exist:
- PENDING (new reservation that needs action)
- CONFIRMED
- REJECTED (or CANCELED)

Logic:
- “New Reservation” card should show ONLY if there is at least 1 PENDING reservation.
- Accept action:
  - update reservation status to CONFIRMED
  - remove it from “New Reservation” card
  - show toast “Reservation accepted”
- Reject action:
  - update reservation status to REJECTED
  - remove card
  - show toast “Reservation rejected”

- Create endpoints:
  - POST /api/reservations/:id/accept
  - POST /api/reservations/:id/reject

If using mock providers:

- Ensure UI updates immediately (optimistic UI) then confirms.
