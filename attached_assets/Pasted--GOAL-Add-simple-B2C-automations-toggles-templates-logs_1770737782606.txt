
GOAL
Add simple B2C automations (toggles + templates + logs) for:
- Check-in automation
- Check-out automation
- Message automation (light)
Plus safety rules:
- Channel-aware pausing (disconnected, missing scopes, unmapped listing)
- Recent automation actions log for trust

-----------------------------------------
1) UI REQUIREMENTS (Settings → Automation)
-----------------------------------------
Add a new Settings item: “Automation”
When opened, show ONE screen (or one subpage under Settings) with these sections:

A) CHECK-IN AUTOMATION
- Toggle: “Auto check-in message” (on/off)
- Send timing selector:
  - “24 hours before check-in” (default)
  - “Morning of check-in”
- Button: “Edit message” (opens template editor sheet)
- Show message preview under the toggle

B) CHECK-OUT AUTOMATION
- Toggle: “Auto thank-you message after check-out” (on/off)

  - Button: “Edit message”
- Toggle: “Cleaning reminder” (on/off)
  - Note: “Notifies you on check-out day”

C) MESSAGE AUTOMATION
- Toggle: “Auto-reply to first guest message” (on/off) (default OFF)
  - Note: “Sends a short acknowledgment message”
  - Button: “Edit message” (optional; can reuse template editor)
- Toggle: “Quiet hours” (on/off)
  - Time range inputs: start/end (e.g., 23:00–08:00)
  - Note: “No auto messages are sent during quiet hours”

D) AUTOMATION SAFETY & VISIBILITY
- “Recent automated actions” list (read-only)
  - Show: type, guest name, listing name, channel, timestamp, status (success/failed/paused)
- Channel-awareness banner when relevant:
  - Example: “Paused for Booking.com (messaging not supported)” or “Paused: Listing unmapped”

IMPORTANT UX RULES
- Keep it simple: no rule builders, no conditions UI.
- All controls are toggles + timing + time range.
- Reuse existing UI components (Card, Toggle, Badge, BottomSheet/Modal, Toast).

- Toggle remains ON, but show “Paused” banner in UI.

3) SERVER LOGIC (SERVICES)
-----------------------------------------
Implement an “automation service” with pure functions and tests where possible:

A) canSendAutomatedMessage(userId, listingId, channelId) -> {ok, reason}
Checks:
- ChannelConnection is CONNECTED
- grantedScopes includes MESSAGES_WRITE
- ExternalListingMap for (listingId, channelId) exists and is MAPPED
If not, return ok=false with reason used in UI/log.

B) quietHoursCheck(now, quietHoursStart, quietHoursEnd) -> boolean
If quietHoursEnabled and current time is within quiet hours:
- do NOT send automated messages
- log PAUSED with reason “QUIET_HOURS”

C) templateRender(body, variables)
Support minimal variables:
- {{GuestName}}
- {{ListingName}}
- {{CheckInDate}}
- {{CheckOutDate}}
(You can add more if you already have them.)

-----------------------------------------
4) AUTOMATION TRIGGERS (MVP)
-----------------------------------------
Implement these triggers with a cron endpoint (server-side). No external queue.

A) Daily cron endpoint
POST /api/cron/daily (protected by CRON_SECRET)
Runs for all users:
1) CHECK-IN message
- If autoCheckinEnabled:
  - Find CONFIRMED reservations where:
    - if timing = CHECKIN_MINUS_24H: checkIn is tomorrow
    - if timing = CHECKIN_MORNING: checkIn is today AND current time is morning (choose 08:00 local)
  - For each reservation:
    - apply quiet hours rule
    - apply canSendAutomatedMessage
    - If ok, create OUTBOUND message (or send via provider adapter if exists)
    - Log action (SUCCESS/FAILED/PAUSED)

2) CHECK-OUT thank-you
- If autoCheckoutThanksEnabled:
  - Find reservations with checkOut = yesterday (send morning after)
  - Apply quiet hours + canSend
  - Send message + log

3) CLEANING reminder
- If cleaningReminderEnabled:
  - For reservations with checkOut = today:
    - create in-app Notification
    - log CLEANING_REMINDER SUCCESS

B) “Auto-reply to first message”
Trigger when an INBOUND message arrives:
- If autoFirstReplyEnabled:
  - If this is the first inbound message in that conversation AND host hasn’t replied yet:
    - Apply quiet hours
    - Apply canSend
    - Send FIRST_REPLY_ACK message
    - Log action
IMPORTANT: Avoid loops. Only trigger once per reservation/conversation.
